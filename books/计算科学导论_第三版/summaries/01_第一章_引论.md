# 第一章细读：引论

## 阅读范围与结构

- PDF 第 20-33 页
- 1.1 计算科学一词的来历
- 1.2 科学哲学与学科方法论简介
- 1.3 一般的科学思想方法
- 1.4 计算科学初学者的正确选择
- 1.5 使用本书应该注意的事项

本章不是全书知识内容的缩写，而是在建立一套阅读框架。作者先解释本书怎样使用“计算科学”一词，再说明为什么认识一门学科需要科学哲学和方法论，随后给出“认识—方法—程序”的一般工作模式，最后把这套模式用于初学者自己的学习。

## 一句话概括

初学者虽然还没有足够专业知识，却可以先借助学科导论建立一张概貌性的地图，再用这张地图指导后续学习，并随着知识增长不断修正它。

## 本章真正的问题

表面上，第一章在讲术语、科学哲学和人才标准；这些内容共同服务于一个更具体的问题：

> 一个尚不了解计算机科学的人，怎样作出合理的学习选择？

这里存在一个认识上的循环：要合理安排专业学习，似乎必须先了解专业；但初学者正因为尚未学习，才不了解专业。作者的解法是暂时跳出专业知识的内部细节，在“科学哲学 + 学科方法论 + 高级科普”的层面先形成概貌。

## 1.1 “计算科学”的来历与边界

### 1. 学科由几条传统汇合而成

作者用一条简化的历史线索说明计算机科学并非由单一技术发展而来：

```text
计算的数学理论 ─┐
电子数字计算机 ─┼─→ 计算机科学逐渐成为独立学科
科学计算应用   ─┤
高级程序设计语言 ┘
```

早期研究者来自数学和电子科学。数学传统追问什么是计算、哪些问题可以计算以及计算的极限；工程传统把自动计算落实为通用电子数字计算机；程序设计语言又把理论、硬件和软件连接起来。大学中的院系分别生长于数学、电子、控制、工程等不同背景，也由此形成计算机科学与计算机工程等不同名称和培养侧重。

作者借 1989 年 ACM 与 IEEE/CS 的《计算作为一门学科》报告，支持用一个较宽的“计算”概念统摄理论、系统、软件、硬件和应用工作。本章没有充分论证报告的结论，而是把严格说明留给第三章。

### 2. “使用计算机”不自动构成计算机科学研究

作者区分两种工作：

- 在应用中产生可跨领域复用的新理论、概念、方法或技术；
- 使用已经成熟的计算机技术解决某个具体行业的问题。

前者可能推进计算机科学本身，后者通常属于相应应用学科。这个划分提醒我们：研究对象使用了计算机，并不意味着研究贡献位于计算机科学。

不过，现实中的边界往往不是二分的。一个医学影像项目可能同时包含临床问题、新算法、系统工程和数据方法；判断其学科贡献时，应看研究问题、原创部分、评价标准和可迁移性，而不能只看使用场景。

### 3. 狭义与广义计算科学

本书对术语作了自己的约定：

- 狭义计算科学：大致指计算机科学与技术，研究一般的计算问题及其理论和实现；
- 广义计算科学：除狭义内容外，还把计算看作理论和实验之外的一种科学研究形态。

广义计算科学通过数学模型、数值方法、计算机模拟、数据处理和可视化研究现实对象。例如飞行模拟、复杂物理系统模拟等，都不是简单地“算得更快”，而是在一个可控制、可重复的模型环境中进行研究。

作者也强调，计算形态不能脱离理论和实验独立存在：模型需要理论规定结构和假设，参数与边界条件来自观察或实验，模拟结果最终还要与现实证据比较。

因此，三者更适合表示成反馈关系：

```text
理论提出模型与预测
   ↕
计算展开模型、探索后果
   ↕
实验提供数据并检验二者
```

模拟产生的是模型在给定条件下的结果，并不会因为使用了计算机就自动变成真实可靠的事实。

## 1.2 为什么计算机导论要讲科学哲学

### 1. 从方法的局限进入哲学问题

作者用演绎和归纳的局限说明：科学不只需要方法，还需要反思方法为什么可靠。

- 演绎可以保证：如果前提为真且推理有效，结论就为真；但演绎本身不能保证初始前提为真。
- 归纳可以从观察中形成一般规律；但有限观察在逻辑上不能保证普遍结论永远成立。

由此出现一组比“怎样计算”更高层的问题：理论中的对象是什么，基本前提从哪里来，知识怎样得到检验，方法在什么条件下合理，理论何时需要修正。

### 2. 科学危机的教育意义

本章以非欧几何、数学悖论和相对论对经典理论的挑战为例，说明成熟理论也有适用范围和基础假设。重要启示不是“旧理论全部错误”，而是：

- 结论必须与前提和论域一起理解；
- 一个系统内部长期无法解决的问题，可能要求改变基本假设或观察层次；
- 科学知识具有可检验、可批判和可修正的结构。

作者据此引出科学哲学：它以科学知识、科学活动和科学方法为研究对象，追问科学与非科学的区别、知识的可靠性以及方法的合理性。

### 3. 本体论、认识论和方法论

按照本章的组织，可把三者粗略理解为：

| 层次 | 主要问题 | 在计算机科学中的例子 |
| --- | --- | --- |
| 本体论 | 研究对象以什么方式存在 | 程序、算法、进程和虚拟对象究竟是什么 |
| 认识论 | 我们如何形成并判断知识 | 怎样知道一个算法正确、一个模型可信 |
| 方法论 | 方法为何合理、何时适用 | 测试与证明各能支持什么结论 |

作者对这些哲学概念的说明主要服务于初学者，不能代替严格的哲学史或专门定义。尤其不能把本体论简单等同于寻找一个不需要任何根据的“最终基础”。

### 4. 方法学与方法论不是一回事

本章以程序设计为例作出重要区分：

- 方法学研究一类具体方法怎样建立和使用，例如怎样组织程序设计以获得高质量程序；
- 方法论把已有方法作为研究对象，比较它们的性质、关系、适用条件、科学性和合理性。

可以简化为：

```text
方法学：怎样做
方法论：为什么这样做、何时这样做、凭什么认为它合理
```

两者并非彼此隔绝。对方法论的认识会指导方法设计，具体方法的成功和失败也会反过来修正方法论。

### 5. 对本节科学史叙述的校正

这一节的目标是快速建立思想背景，因此把漫长而多线的科学史压成了一条单线，阅读时需要谨慎：

- 演绎、归纳、实证和科学哲学并非简单依次取代，而是长期并存、互相修正；
- 科学与哲学的关系不能简化成谁“高于”谁；
- 欧氏几何与牛顿力学在各自适用范围内仍然有效，新理论通常是限定和扩展旧理论，而非简单推翻；
- 原文把苏格拉底称为亚里士多德的学生，这是明显的历史错误；苏格拉底早于亚里士多德，二者并无这种师生关系。

这些问题不影响本节的中心提醒：学习一门科学，既要会使用方法，也要知道方法的根据和边界。

## 1.3 一般的科学思想方法

### 1. 作者提出的基本链条

本章最重要、也最容易迁移的框架是：

```text
科学的认识 → 科学的方法 → 科学的程序
```

- 科学的认识：从多个视角理解对象的性质、结构、限制和变化规律；
- 科学的方法：根据这种认识选择、建立、改进或组合解决办法；
- 科学的程序：把方法落实为明确步骤，规定检查方式以及异常处理。

作者借理科院校与工科院校的不同传统，说明只追求立即见效容易依赖经验试错，只追求理论体系又可能远离现实问题。这个院校分类明显带有当时教育环境的概括，不能机械套用；真正有价值的是基础研究与工程实践之间的分工。

### 2. 这不是只能单向执行的瀑布流程

原文的表述容易让人以为必须先获得完整认识，才能选择方法，最后才开始行动。现实中，复杂问题往往无法预先认识完整。更合理的现代解释是循环：

```text
初步认识 → 选择方法 → 小规模执行 → 收集证据
    ↑                              ↓
    └──────── 修正认识与方法 ────────┘
```

作者在再版前言中根据教学反馈修改教材，其实已经实践了这种循环。

### 3. 十个问题不是知识测验

本章列出的十个“奇怪问题”并不要求统一答案，它们分别训练不同的思维动作：

| 问题 | 主要训练 |
| --- | --- |
| 怎样判断字写得好 | 从功能和属性建立评价标准 |
| 美是否都简单 | 澄清概念、寻找反例、限定命题 |
| 数学、逻辑与新闻的联系 | 跨领域抽象与证据推理 |
| 知识越多是否越妨碍创新 | 拆解表面矛盾，区分知识与教条 |
| 什么是艺术 | 使用内涵、外延和边界案例定义概念 |
| 怎样培养创新人才 | 把口号拆成主体、条件和可执行措施 |
| “身在庐山”对应什么科学实例 | 改变观察尺度和系统边界 |
| 哪一门是领头学科 | 先定义评价维度，再作事实判断 |
| 怎样初判暂不可验证的新理论 | 在不确定性下评价来源、证据和一致性 |
| 是否“证比求易” | 区分寻找解与验证解，引向复杂性问题 |

这些题目的共同要求是：先把模糊问题变成可讨论的结构，再提出能被反驳和修正的答案。

## 1.4 初学者的“正确选择”

### 1. 作者的人才标准

作者认为高素质专业人才至少要同时具备：

1. 品德和人文素养；
2. 坚实的专业基础和专业功底；
3. 创新意识与科学思想方法。

理工科人才还需要把上述共性落实为解决理论、技术和工程问题的实践能力。这里值得注意的是，作者没有把“会使用计算机”列为最高层目标，因为它只是专业能力的一种外在表现。

### 2. 初学者的认知循环

本节提出一个很真实的困难：

```text
合理学习需要先理解学科
        ↕
理解学科又需要先进行学习
```

作者用“跳出系统”的方式解开循环：初学者暂时不从专业细节内部认识学科，而从高级科普和科学哲学层面获得定义、范围、基本问题、发展主线、知识结构和工作流程。这不是完整知识，而是学习所需的脚手架。

因此，导论给出的地图应被看成暂定模型。随着学习推进，学生必须允许后续课程和真实项目修正最初认识，而不是把导论中的分类当成永远不变的标准答案。

### 3. 对“正确选择”的保留

作者把重基础、反对短期实用主义表达得很有力量，但有时把自己的培养路线称为“科学规律”，论证强度超过了所给证据。课程选择还会受到目标、兴趣、资源、行业和个人条件影响。

更稳健的结论是：不要只由当前流行工具决定长期学习路线；应根据目标，在可迁移基础、工程实践和具体技术之间形成有意识的组合，并定期复盘。

## 1.5 作者与读者订立的学习契约

本节说明怎样使用全书：

- 不指望从导论获得系统的专门技术；
- 第一次不理解某些术语是正常的，先知道它们位于何处；
- 尽快通读前四章，再在后续学习中反复返回；
- 把观点与个人经验和实际问题联系，而不是只背结论；
- 课程结束后独立写读书报告，形成自己的学科认识和学习规划；
- 对重要课程和实验持续写报告，训练论证、表达和复盘能力。

作者要求计算机专业学生不满足于操作技巧，而要追问“为什么”。这一要求有价值，但不必把专业与非专业学习者绝对对立；严谨理解和深入实践并非科班学生的专属品质。

## 全章论证地图

```text
计算机科学来自理论、硬件、软件和应用的汇合
                         ↓
学科边界不能用“是否使用计算机”判断
                         ↓
要理解学科，必须追问知识和方法的根据
                         ↓
形成“认识—方法—程序”的一般工作框架
                         ↓
用该框架分析初学者自己的学习问题
                         ↓
先借导论建立概貌，再由课程和实践持续修正
```

## 用一个实际问题检验本章框架

假设目标是“学会开发一个可靠的网络服务”。

### 科学的认识

先理解请求模型、并发、数据一致性、故障、延迟、安全和运行环境，而不是立即挑选一个热门框架。

### 科学的方法

根据需求选择协议、数据模型、并发控制、测试策略、监控方式和部署架构，并说明每项选择的适用条件。

### 科学的程序

把工作落实为需求定义、最小原型、测试、负载实验、故障注入、部署、监控和复盘步骤；实际证据再返回前两层，修正认识和方法。

这说明“重基础”并不等于推迟实践，而是让实践成为有假设、有检验、有反馈的活动。

## 第一章总结

第一章完成了三件事。第一，它界定本书的“计算科学”并把计算放到更广的科学研究背景中；第二，它用演绎与归纳的局限说明为什么学习具体技术还不够，还要理解知识和方法的根据；第三，它把“认识—方法—程序”应用到学习本身，提出先建立学科地图、再逐步深入的路线。

本章最值得带入后文的不是某一段科学史，而是三个习惯：讨论前先澄清概念和边界，行动前先形成关于对象的模型，行动后用证据修正模型。
