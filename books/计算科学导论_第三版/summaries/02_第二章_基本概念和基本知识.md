## 一句话概括

计算机系统之所以能够处理复杂问题，是因为计算被逐层表示、翻译和实现：抽象模型变成算法，算法写成程序，程序经语言和系统软件转成指令，指令由逻辑电路执行，多个部件和机器再通过体系结构、并行与网络组成更大的计算环境。

## 全章知识地图

```text
问题与数学性质
       ↓ 抽象
计算模型与可计算性
       ↓ 构造
算法与复杂性
       ↓ 表达
程序、数据结构与高级语言
       ↓ 翻译
编译器 / 解释器 / 汇编器
       ↓ 执行接口
机器指令与指令系统
       ↓ 实现
布尔逻辑、数字电路与物理器件
```

这条纵向链条由操作系统和系统软件组织起来，又向体系结构、并行计算、网络、高性能计算、图形和人工智能等大型应用领域横向展开。

贯穿所有层次的四个动作是：

```text
抽象 → 表示 → 翻译 → 执行
```

贯穿所有层次的三个评价问题是：能不能算、算得是否正确、资源代价是否可接受。

## 2.1 计算模型、图灵机与二进制

### 1. 形式化先忽略内容差异

作者用梨和橘子的例子解释形式化：当我们只保留“数量”这一结构时，不同物品都可以表示成同一个算式。形式化不是说具体内容不重要，而是为了研究某类关系，主动选择相关特征并暂时隐藏其他差异。

这一动作在计算机科学中无处不在：

- 图把城市、用户或网页抽象成结点和边；
- 数据类型隐藏对象的内部存储；
- 状态机忽略系统材料，只研究状态与转换；
- 协议把通信行为压缩成消息、顺序和规则。

形式化的力量来自可迁移性，风险则来自遗漏。如果被隐藏的特征实际影响结论，模型就会失真。

### 2. 计算模型不是某一道题的计算公式

梯形面积公式或一元二次方程求根公式，只解决特定问题。图灵机、递归函数、λ 演算和 Post 系统则试图刻画一般意义上的机械计算。

作者给“计算模型”划分了若干层次，原文表述较绕，可以重新整理为：

| 层次 | 回答的问题 | 例子 |
| --- | --- | --- |
| 特定求解模型 | 某类题怎样计算 | 数值积分公式 |
| 程序执行平台 | 某种表示怎样运行 | 语言运行环境、虚拟机 |
| 一般计算模型 | 什么叫机械计算 | 图灵机、λ 演算、递归函数 |
| 语义模型 | 符号系统怎样获得解释 | 公理系统或语言的模型 |

第四层与前三层的“模型”含义并不完全相同：前三层侧重计算机制，第四层更接近逻辑和语义中的解释结构。阅读时不要因为都叫“模型”就把它们混成一个概念。

### 3. 图灵机怎样刻画计算

一台基本图灵机包含：

- 可向两端延伸、划分为格子的纸带；
- 有限符号表；
- 有限状态集，含开始和停机状态；
- 可以读写并移动的读写头；
- 根据“当前状态 + 当前符号”决定下一动作的转换规则。

一次转换完成三件事：写入符号、移动读写头、改变状态。复杂计算由大量简单、局部、明确的状态转换组成。

从不同视角，图灵机可以被看作：

- 识别器：判断输入是否属于某个语言；
- 生成器：研究给定规则可以产生哪些输出；
- 计算器：把输入映射为函数值。

图灵机的价值不在于模仿现代计算机的外形，而在于用极少结构捕捉程序执行的关键特征：离散状态、存储、规则和逐步变换。

### 4. “等价”与 Church-Turing 论题

多种形式计算模型之间的计算能力等价，可以在各自的数学定义下证明。但是，“一切直观上可由算法完成的计算都能被这些模型表达”并不是普通意义上可由实验穷尽证明的定理，而通常被理解为 Church-Turing 论题。

这一区分很重要：

- 形式模型之间的等价是数学结论；
- 形式模型是否覆盖所有直观能行计算，是连接形式定义与非形式概念的论题。

### 5. 判定、半判定与不可判定

判定问题要求对某类输入回答“是”或“否”。可判定意味着存在一个对所有合法输入都能终止并给出正确答案的算法。

半可判定通常意味着：对于答案为“是”的实例，某个过程最终能够确认；对答案为“否”的实例，它可能永不停止。不可判定则表示不存在满足完全判定要求的算法。

因此，“命题客观上有真假”与“我们有算法总能判定真假”是两件事。第二章只是建立入口，严格内容属于可计算性理论。

### 6. 为什么二进制适合数字计算机

二进制首先是一种位置记数制。它适合数字系统主要因为：

- 两种状态较容易用物理器件的稳定状态表示；
- 基本运算规则较少；
- 0/1 可以在适当解释下与布尔逻辑建立对应；
- 文字、声音、图像和指令都能编码成统一的离散形式。

这里要区分数值与语义。二进制中的 0 和 1 原本是数字，布尔代数中的 0 和 1 可以解释为假与真，电路中的低、高电平又是物理状态。三者通过人为规定和工程设计建立对应，并非天然就是同一个对象。

本节关于字符编码的内容具有历史背景。更持久的认识是：计算机不能直接“认识”文字或图像，必须先约定编码；编码决定符号怎样映射为比特序列，解释编码的系统再恢复其意义。

## 2.2 存储程序式计算机

### 1. 核心思想是“程序也可以存储”

存储程序式计算机把指令和数据编码后存入存储器。控制器按程序规定取出指令并组织执行，使同一套硬件通过更换程序完成不同任务。

传统结构由五类部件构成：

- 输入设备；
- 存储器；
- 运算器；
- 控制器；
- 输出设备。

运算器和控制器通常合称 CPU。典型执行循环可以概括为：

```text
取指 → 译码 → 取操作数 → 执行 → 保存结果 → 更新下一条指令位置
```

“顺序控制”不表示程序只能从上到下一成不变地运行。分支、循环、调用、异常和中断都会改变控制流；关键是下一步仍由机器状态和规则明确决定。

### 2. 通用性的来源

通用计算机并不是预先制造了每一种应用功能，而是提供一套足够一般的基本操作，让不同程序重新组织这些操作。这是“有限机器描述大量行为”的核心机制。

### 3. 硬件、软件与计算机系统

裸机只提供机器级资源和指令，人与机器之间仍有巨大语义距离。汇编器、编译器、操作系统、数据库和开发工具逐层隐藏细节、管理资源并提供更适合人的接口。

因此：

```text
计算机系统 = 硬件 + 系统软件 + 应用软件及其运行环境
```

作者把人的日常活动类比为执行程序，这有助于说明“预先安排步骤”，但不能据此把人等同于确定性计算模型。人的行为受到身体、环境、社会和反思活动影响，远比书中的比喻复杂。

## 2.3 数字逻辑与集成电路

### 1. 布尔代数是三个世界的桥

```text
逻辑：真 / 假
  ↕
代数：0 / 1 及其运算
  ↕
电路：低 / 高电平与逻辑门
```

与、或、非等布尔运算可以用逻辑门实现。组合逻辑的输出主要取决于当前输入；时序逻辑还包含状态或记忆，其输出与过去状态有关。加法器、寄存器、控制部件等都可以由这些基本结构组合而成。

这展示了计算机科学的一种典型路线：先建立形式系统，再找到物理实现，使符号推演成为真实设备中的状态变化。

### 2. 计算能力与实现技术不同

同一种计算规则可以由机械、电路、程序或其他介质实现。更快的器件、更大的指令集或更多逻辑门会改变速度、能耗、成本和便利性，却不一定扩大理论上的可计算范围。

因此要区分：

- 可计算性：原则上能否计算；
- 计算复杂性：需要多少资源；
- 工程实现：用什么器件和结构达到目标。

## 2.4 机器指令与汇编语言

机器指令通常包含操作码和操作数位置等信息。指令系统规定处理器能够直接执行哪些基本操作，也构成软件与硬件之间的重要接口。

汇编语言给机器指令提供助记符号和地址表示；汇编器再将汇编程序转换为机器代码。两者通常关系紧密，但汇编语言仍是一种符号表示，不能直接等同于硬件电路。

本节借复杂指令与精简指令讨论一个长期存在的设计原则：

```text
把复杂性放在哪一层？

硬件承担更多功能 ←→ 编译器和软件组合简单指令
```

更多指令可能方便某些程序，却增加译码和实现复杂度；较简单、规则的指令可能便于流水线和优化，却要求软件完成更多组合。RISC 与复杂指令系统不应被理解成永远互斥的纯粹类型，真实系统常吸收双方思想。

本节认为汇编程序通常比高级语言编译结果更高效，这种概括也不能机械套用。手写低层代码可以精确控制局部实现，但现代优化器能够进行大量跨指令、跨过程和面向具体处理器的优化。应以测量和约束判断，而不是仅凭语言层次下结论。

## 2.5 算法、过程与程序

### 1. 四个相邻概念

| 概念 | 关注点 |
| --- | --- |
| 计算方法 | 解决问题采用什么数学或结构思想 |
| 算法 | 把方法精确化为能行、可执行的有限规则 |
| 程序 | 用某种语言和工程结构表示计算行为 |
| 执行过程 | 程序在特定输入和环境中的动态运行 |

同一种方法可以产生不同算法，同一算法可以有多种程序实现，同一程序又会因输入、调度和环境产生不同执行过程。

最大公因数例子说明：算法的正确性来自数学性质，程序只是这种算法的一种形式。程序变换可以大幅改变代码外观，因此“看起来像原算法”不是正确性标准，关键在于变换是否保持语义。

### 2. 算法的基本要求

本章采用的经典描述包括：

- 有穷性：对规定输入在有限步骤后结束；
- 确定性：每一步含义明确；
- 输入：可以有零个或多个输入；
- 输出：产生与输入满足规定关系的结果；
- 能行性：基本操作能够机械、精确地执行。

书中把某些可能永不终止的有效规则称为“过程”，并提醒这不同于程序设计语言中作为子程序的 procedure。

经典定义很适合顺序确定性算法，却不容易直接覆盖随机、交互、并行、分布式或持续运行的系统。这也说明概念定义会随着研究对象扩大而调整。

### 3. 存在解不等于存在算法

连续函数零点的例子区分了数学存在性和有限表示：定理可以保证精确零点存在，但若结果是无法用有限位数完整表示的实数，要求机器输出“精确值”可能使计算永不终止。实际算法必须改写任务，例如给出误差范围内的近似值。

这揭示了规格的重要性：

```text
问题是否可计算，不只取决于对象，还取决于输入、输出和精度怎样定义。
```

### 4. 可计算不等于实际可行

算法存在后，还必须研究资源代价。复杂性分析不直接采用某台机器的秒数，而考察问题规模增大时，抽象基本操作次数或存储需求的增长规律。

因此，复杂度是关于增长率的模型，而不是一次运行的计时结果。实际性能还会受到常数、缓存、并行度、输入分布、编译器和硬件影响。

筛法例子表明，高效算法来自对问题结构的认识，而不是单纯换一台更快的机器。数学性质既支持正确性证明，也可能带来数量级上的效率改进。

### 5. 时间、空间与并行资源

“证比求易”的故事用三种思路说明资源差异：

- 顺序尝试：占用空间少，时间可能很长；
- 大量人员同时尝试：用更多处理资源换时间；
- 猜测后验证：引出非确定性计算的抽象。

它的价值在于展示时间与空间、顺序与并行、寻找与验证的区别。故事中的具体数字并非严谨算法实例，书中脚注也提醒其可能不满足所述整除关系。

### 6. P、NP 与 NP 完全性

本节只适合建立直观位置：

- P：可由确定性模型在多项式时间内判定的问题；
- NP：可以把“是”的证据在多项式时间内验证的问题，等价地可由非确定性图灵机在多项式时间内判定；
- NP 完全问题：位于 NP 中，且所有 NP 问题都能以适当方式归约到它。

若任一 NP 完全问题存在多项式时间算法，则所有 NP 问题都有多项式时间算法。反过来，证明某个 NP 完全问题不属于 P，即可推出 P ≠ NP。

原文把“多数实际问题都属于 NP”说得过宽。P 和 NP 是针对具有形式定义的判定问题类别，现实任务必须先形式化，不能仅凭“寻找难、验证易”的印象直接分类。

### 7. 程序比“数据结构 + 算法”更宽

“程序 = 数据结构 + 算法”是有启发性的设计口号，却不是完整定义。程序还可能包含交互、并发、外部状态、长期服务、配置和错误处理；有些程序的目的不是计算一个最终结果，而且可能有意持续运行。

编译和解释则是高级表示获得执行意义的两种基本方式：编译偏向先整体转换出目标程序，解释偏向在运行过程中分析并执行。真实语言实现也可能组合两者。

## 2.6 高级语言与程序设计方法

高级语言通过更接近问题结构的语法和语义，隐藏寄存器、地址和机器编码等细节。语言并非只替换指令名称，它还承载程序设计观念，例如过程抽象、类型、模块、对象、函数、逻辑关系、约束和并发。

作者列出的自顶向下、自底向上、程序推导、程序变换、面向对象、函数式、逻辑式、并发和验证方法，角度各不相同，共同目的都是控制复杂性并提高正确性、可读性、复用性与效率。

本节提出“语言是计算模型的外在表现形式”。可以把它理解为：语言规定了可表达的结构、基本操作和组合规则，从而给程序员呈现一种计算世界。严格来说，语言、语言语义、执行模型和具体实现仍需区分，不能因为一种语言表达能力很强，就认为所有实现具有相同效率。

## 2.7 系统软件与应用软件

软件不只是程序文本，还包含支撑其开发、使用和维护的文档、规范、数据、配置及其他工件。随着系统变复杂，软件概念必然从单个程序扩展到整个生命周期。

系统软件管理硬件资源并为其他程序提供平台，例如操作系统、编译器、汇编器、运行库和开发工具。应用软件面向具体用户任务。二者边界具有相对性：数据库管理系统、浏览器、虚拟机或平台服务，在不同系统中可以扮演不同角色。

比记住分类更重要的是理解系统软件的两项功能：

```text
向下：管理、调度和保护真实资源
向上：提供稳定接口并隐藏机器细节
```

## 2.8 图形学、图像处理与模式识别

三者可以按信息流向区分：

```text
图形学：模型 / 几何数据 → 图像
图像处理：图像 → 改善、压缩或变换后的图像
模式识别：图像 / 数据 → 类别、结构或模型
```

计算几何则研究几何对象的表示、构造和算法。它为图形学、空间数据处理和形状分析等工作提供数学基础。

这种区分在实际系统中会交叉。例如一个视觉系统可能先进行图像去噪，再提取结构，最后根据识别结果生成新的可视化。

## 2.9 逻辑与人工智能

本节从“让机器承担需要推理的工作”引出人工智能，并介绍三条历史路线：

- 用逻辑系统刻画知识和推理；
- 借认知心理学研究人的信息处理过程；
- 通过演化计算等机制搜索和优化。

作者把人工智能概括为让机器模拟人的行为。这适合说明早期目标，却不是唯一可能的定义：许多智能系统追求完成任务、学习规律或作出决策，并不要求内部过程复制人类。

本节最稳健的判断是：逻辑揭示了智能的一部分结构，但不是智能的全部；人工智能依赖对表示、学习、推理、感知、语言、行动和评价标准的共同研究。

书中认为自然语言编程仍是十分遥远的设想，也把人工智能的若干路线描述为尚未取得根本突破。这些判断应视为成书时代的历史截面，而不是全书中最具长期性的结论。

## 2.10 计算机组织与体系结构

本节给出一个经典区别：

- 体系结构关注软件尤其是机器级程序能够看到的抽象接口和系统组织；
- 计算机组成关注这些接口怎样由处理器、存储器、互连和控制部件实现。

同一体系结构可以有多种具体实现，从而实现软件兼容。体系结构也不只是硬件问题，它需要在指令集、编译器、操作系统、存储系统和互连之间分配功能与复杂性。

这里再次出现“透明性”：底层屏蔽通信、存储和设备细节，向上层提供较稳定的功能视图。抽象能够降低使用难度，但也可能隐藏性能和故障特征，因此系统设计既需要透明接口，也要在必要时允许观察底层行为。

## 2.11 并行计算与通道

并行性可以存在于多个层次：

- 作业或程序级；
- 任务或过程级；
- 指令级；
- 指令内部级。

Flynn 分类按照指令流与数据流的数量，把结构分成 SISD、SIMD、MISD 和 MIMD。这是观察体系结构的一种坐标，不是对所有现代系统的完整分类。

本节还区分并发与并行：并发强调多个活动在同一时间段内推进，并不保证物理上同时执行；并行强调多个资源在同一时刻实际执行多个活动。

I/O 通道和专用处理部件说明，性能瓶颈不能只靠加快 CPU 解决。让数据传输与计算重叠，可以提高系统吞吐量。并行系统也再次证明算法与平台不可完全分开：数据怎样分解、处理器怎样通信、同步成本多大，都会改变算法的实际效率。

## 2.12 网络与通信

网络源于资源共享、远距离通信和问题本身的地域分布。网络系统不仅包含连接机器的线路和设备，还需要协议、网络软件和操作系统协调各结点。

通信协议规定消息格式、顺序、控制方式和异常处理。分层结构把复杂通信拆成相对独立的服务，每层使用下层能力并向上层提供接口。OSI 七层模型在本章中的主要价值不是要求死记七个名称，而是展示分层和封装思想：

```text
应用需求
   ↓
逐层转换、分组、寻址、传输
   ↓
物理信号
```

接收端则反向逐层解释。所谓同层协议描述逻辑上的通信关系，实际数据仍要通过下层一路传输。

网络同时扩大了共享能力和攻击面。书中的病毒、加密和访问安全讨论较为初步，但已经指出安全不是某个单独软件的附加功能，而同时涉及技术、管理、法律和人的行为。

本节对网上购物、远程医疗和网络会议等内容使用未来式，明显反映写作年代。其长期价值在于协议分层、资源共享、可靠传输和安全边界等基础概念。

## 2.13 高性能计算

本节按主要瓶颈把高性能任务分为：

- 计算密集；
- 数据密集；
- 通信密集。

高性能不等于只有 CPU 峰值速度。处理能力、存储容量、内存带宽、通信延迟和 I/O 必须均衡，软件、算法、能耗、冷却、可靠性和成本也共同决定实际性能。

这一节呼应第一章的广义计算科学：复杂系统可以通过模型和模拟进行研究。但“计算取代实验”的说法需要限制。模拟依赖理论和数据，其结果还需要验证、校准和不确定性分析；计算更常见的作用是补充、引导或缩小实验范围。

“信息高速公路”“数字地球”和当时的国家信息化工程属于特定历史语境。它们展示了作者怎样从计算、通信和数据整合推想大规模数字基础设施，但不应作为今天的技术现状说明。

## 本章的四条深层主线

### 1. 抽象层次

每一层都隐藏下一层的部分细节，并向上一层提供较稳定的概念。程序员可以使用函数而不必每次设计门电路，但理解层间关系有助于解释性能、正确性和故障。

### 2. 表示与语义

比特、指令、程序和协议报文本身只是形式。编码规则、语言语义、机器结构和通信协议赋予它们意义。形式相同不保证解释相同，正确翻译必须保持语义。

### 3. 能行性与资源

“存在数学解”“存在算法”“可以在现实资源内计算”是三个不同判断。计算机科学不仅问能不能，还问时间、空间、通信、能耗和可靠性代价。

### 4. 理论与实现的双向作用

理论决定哪些系统可能正确构造，工程平台又改变哪些算法值得研究。并行、网络、人工智能和高性能计算都不是纯理论或纯硬件问题，而是模型、算法、软件与系统共同演化的结果。

## 对本章若干表述的批判性阅读

- 形式化模型能否覆盖所有直观算法，应区分数学定理与 Church-Turing 论题；
- “构造性数学描述即可由计算机求解”的说法需要严格限定表示、终止和资源条件；
- 计算模型、数学模型和语义模型在原文中有时使用同一个“模型”名称，含义并不一致；
- 人的行为与程序、脑细胞与存储器的类比只适合帮助入门，不能当成认知科学结论；
- P、NP 是形式化的判定问题类别，不能直接用“多数实际问题”笼统概括；
- 高级语言、汇编语言和 RISC 的效率判断受具体编译器、体系结构与工作负载影响；
- 系统软件与应用软件、图形与图像等边界是分析工具，不是绝对不变的自然分类；
- 人工智能、网络应用和信息化预测应按 2004 年前后的历史材料阅读。

## 第二章总结

第二章的真正贡献不是介绍了十三个领域，而是让我们第一次看见计算机科学的纵向结构：数学和逻辑提供形式基础，计算模型规定能行计算，算法给出求解步骤，程序和语言表达算法，系统软件完成翻译与资源管理，指令和电路实现执行，体系结构、并行与网络把单机扩展成大规模计算系统。

学习后续课程时，可以始终追问四件事：它处在哪一个抽象层，向上提供什么能力，向下依赖什么机制，跨层时必须保持什么语义或性质。

1. 计算模型与特定问题的数学公式有什么区别？
2. 为什么多种形式模型等价，不等于已经用数学证明它们覆盖所有直观算法？
3. 二进制、布尔值和电平信号怎样建立对应，又为什么不能直接混同？
4. 存储程序思想为什么让同一硬件成为通用机器？
5. “存在解”“存在算法”和“实际算得动”分别需要什么条件？
6. 算法、程序和执行过程如何区分？
7. 编译器、操作系统和协议层分别隐藏了哪些下层细节？
8. 并发与并行有什么区别？为什么并行算法依赖体系结构？
9. 高性能系统为什么不能只比较 CPU 速度？
10. 能否为一个熟悉的软件功能画出从问题、算法、程序到指令和硬件的层次链？
