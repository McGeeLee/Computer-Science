# 第14章：元组、集合和字典

## 本章主线

这一章比较三种不同的数据组织方式。选择容器时应从操作需求出发：是否需要保持顺序、允许重复、按位置访问、快速判断成员，还是按键查值。

## 三种容器

### 元组

元组是有序且不可变的序列，适合表示结构固定的一组值、函数的多个返回值或不应被原地修改的记录。不可变的是元组中的引用位置；如果元组包含可变对象，那个对象的内部仍可能变化。

### 集合

集合保存不重复元素，适合成员测试、去重及集合代数。并、交、差、对称差、子集和超集直接表达很多自然语言关系。集合不承诺用于位置访问的稳定顺序，因此不能把下标逻辑套在集合上。

### 字典

字典把唯一的键映射到值，适合根据标识符快速查找记录。添加、修改、读取和删除都围绕键进行。遍历时应明确需要键、值还是键值对，并决定缺失键是错误还是应使用默认值。

## 性能意识

列表成员测试通常需要逐个检查，集合和字典利用哈希结构，在常见情况下能更快判断成员或查找键，但需要元素或键可哈希。性能不是唯一标准：顺序、重复、可读性和数据语义同样重要。

书中的关键字统计和词频案例展示了两个典型模式：用集合回答“是否属于”，用字典回答“每个对象对应多少或什么值”。

## 常见陷阱

- 用集合去重后仍期待保留特定位置顺序。
- 访问不存在的字典键而未决定处理策略。
- 把可变对象当作集合元素或字典键。
- 只因集合查找快就替换列表，却丢失了重复次数或顺序信息。

## 最小练习

读取一段文本：用列表保留单词顺序，用集合统计不同单词，用字典统计词频。比较三个容器回答同一问题时的表达方式。

## 检查点速答（14.1～14.25）

- **元组（14.1～14.6）**：列表可变，元组的元素位置不可增删或替换；`tuple(lst)` 与 `list(t)` 可互转，所以 `append`、`remove`、`t[0]=...` 对元组都无效。变量 `t1 = t2` 可以重新绑定。对 `(1,2,3,7,9,0,5)`，`t[0]=1`、`t[1:3]=(2,3)`、`t[-1]=5`；最大值 9、最小值 0、和 27、长度 7。元组按元素字典序比较。
- **集合创建（14.7～14.10）**：空集合必须写 `set()`，`{}` 是空字典。列表、元组和集合都能容纳不同类型，但集合元素必须可哈希；`{1,3,4}` 和 `{(1,2),(4,5)}` 合法，嵌套集合或列表作为元素不合法。`set(lst)` 去重，`list(s)`、`tuple(s)` 转回时不要依赖位置顺序。
- **集合修改和关系（14.11～14.14）**：添加已存在元素没有效果；`remove` 不存在的元素抛出 `KeyError`。子集/超集比较表示包含关系而不是字典序：`{1,2} < {1,2,4}` 和 `<=` 都为真，而 `{1,2,3}` 与 `{1,2,4}` 互不为子集。`{1,4,5,6}` 的长度、最大、最小、和分别是 `4,6,1,16`。
- **集合运算（14.15～14.17）**：对 `{1,4,5,6}` 与 `{1,3,6,7}`，并集是 `{1,3,4,5,6,7}`，交集 `{1,6}`，前者减后者 `{4,5}`，对称差 `{3,4,5,7}`；对应运算符是 `|`、`&`、`-`、`^`。打印集合时元素顺序不应作为答案的一部分。
- **字典基础（14.18～14.22）**：空字典是 `{}`；每个条目由键和值组成，键必须可哈希，值可为列表等可变对象。`d[key]=value` 可新增或覆盖，`+=` 更新现值，`del d[key]` 删除。`keys()`、`values()`、`items()` 分别提供键、值和键值对视图。
- **字典输出（14.23～14.25）**：示例中 `d["red"]` 是 4，`"blue" in d` 为真、`"purple" in d` 为假，蓝色值加 10 后为 11；重复给 `"susan"` 赋值只覆盖旧值，所以最终键数为 4。`d[key]` 在缺键时抛 `KeyError`，`d.get(key)` 返回 `None` 或指定默认值。现代 Python 字典保持插入顺序，但查值语义仍由键而非位置决定。
