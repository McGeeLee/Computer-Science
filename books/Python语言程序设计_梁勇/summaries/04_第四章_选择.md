# 第4章：选择

## 本章主线

选择结构使程序能够根据条件走不同路径。关键不是记住 `if` 的拼写，而是把自然语言规则转换成互斥、完整且可测试的布尔条件。

## 核心知识

- 比较运算产生布尔值 `True` 或 `False`。
- 单向 `if` 在条件成立时执行一段代码；`if-else` 表示两条互斥路径；`if-elif-else` 依次检查多个条件，只执行第一条满足条件的分支。
- `and`、`or`、`not` 组合条件。写复杂条件时，应先用括号表达逻辑结构，再考虑运算符优先级。
- 嵌套选择适合有层次的决策，但层次太深通常说明条件或函数需要重新组织。
- 随机数可用于模拟和测试，但一次随机结果不能证明程序正确；必要时应固定输入或随机种子以复现问题。
- 条件表达式适合非常短的二选一结果，不适合容纳复杂业务逻辑。

## 设计条件的方法

先列出可能情况及边界，再决定条件顺序。例如把分数映射为等级时，要明确 59/60、89/90、非法负数和超过上限的输入。多个范围条件最好画成数轴或真值表，检查是否有重叠和遗漏。

## 常见错误

- 把赋值、比较或字符串类型混淆。
- 忘记缩进，或让本应属于分支的语句落在分支之外。
- 组合区间时漏写一侧比较，或误解 `and` 与 `or`。
- 多向选择顺序不当，让宽泛条件提前截获了更具体的情况。
- 只测试正常输入，没有测试等于边界、刚小于边界和刚大于边界的值。

## 最小练习

实现一个运费、税率或票价计算器。先写决策表，再实现代码；为每个边界至少准备三个测试值，并解释为什么这些测试足以覆盖所有分支。

## 检查点速答（4.1～4.37）

- **比较与布尔值（4.1～4.4）**：六个比较运算符是 `==`、`!=`、`<`、`<=`、`>`、`>=`；`int(True)=1`、`int(False)=0`，`bool(4)` 为真而 `bool(0)` 为假。不要把 `=`（赋值）与 `==`（相等比较）混用。
- **随机整数**：`randrange(20)` 产生 `0≤i<20`；`randrange(10, 20)` 产生 `10≤i<20`；`randint(10, 50)` 两端都包含；随机得到 0 或 1 可用 `randint(0, 1)`。
- **分支结构（4.5～4.18）**：单向 `if` 可能不执行，`if-else` 恰好选择一边，`if-elif-else` 只执行第一个成立分支。成绩等级应从 `>=90`、`>=80`、`>=70`、`>=60` 依次判断，否则较宽条件会提前截获输入；`else` 总与同一缩进层次最近的未配对 `if` 结合。
- **缩进就是结构**：同样的条件若缩进不同，输出也会不同。把本应只在条件成立时执行的语句退到左侧，会让它无条件执行；漏写冒号、缩进不一致或把 `elif` 放错层次都会产生语法或逻辑错误。
- **逻辑运算（4.19～4.34）**：优先级是 `not` 高于 `and`，`and` 高于 `or`；区间可写成 `low <= x <= high`。异或可写为 `(a and not b) or (b and not a)`；`True or True and False` 与 `True and True or False` 都为 `True`。
- **典型条件**：闰年规则是“能被 400 整除，或能被 4 整除但不能被 100 整除”。`newLine = count % 10 == 0` 可直接保存布尔结果。条件表达式适合写成 `x if condition else y` 的简单二选一。
- **优先级与结合性（4.35～4.37）**：先括号，再幂，再一元运算、乘除、加减、比较、逻辑运算；`**` 是右结合的，因此不要笼统认为所有二元运算符都从左到右结合。复杂式子应加括号表达意图。
