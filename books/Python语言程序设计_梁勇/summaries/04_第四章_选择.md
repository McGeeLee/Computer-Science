# 第4章：选择

## 本章主线

选择结构使程序能够根据条件走不同路径。关键不是记住 `if` 的拼写，而是把自然语言规则转换成互斥、完整且可测试的布尔条件。

## 核心知识

- 比较运算产生布尔值 `True` 或 `False`。
- 单向 `if` 在条件成立时执行一段代码；`if-else` 表示两条互斥路径；`if-elif-else` 依次检查多个条件，只执行第一条满足条件的分支。
- `and`、`or`、`not` 组合条件。写复杂条件时，应先用括号表达逻辑结构，再考虑运算符优先级。
- 嵌套选择适合有层次的决策，但层次太深通常说明条件或函数需要重新组织。
- 随机数可用于模拟和测试，但一次随机结果不能证明程序正确；必要时应固定输入或随机种子以复现问题。
- 条件表达式适合非常短的二选一结果，不适合容纳复杂业务逻辑。

## 设计条件的方法

先列出可能情况及边界，再决定条件顺序。例如把分数映射为等级时，要明确 59/60、89/90、非法负数和超过上限的输入。多个范围条件最好画成数轴或真值表，检查是否有重叠和遗漏。

## 常见错误

- 把赋值、比较或字符串类型混淆。
- 忘记缩进，或让本应属于分支的语句落在分支之外。
- 组合区间时漏写一侧比较，或误解 `and` 与 `or`。
- 多向选择顺序不当，让宽泛条件提前截获了更具体的情况。
- 只测试正常输入，没有测试等于边界、刚小于边界和刚大于边界的值。

## 最小练习

实现一个运费、税率或票价计算器。先写决策表，再实现代码；为每个边界至少准备三个测试值，并解释为什么这些测试足以覆盖所有分支。

## 自测

- `if-elif-else` 为什么只执行第一条成立的分支？
- 怎样发现条件范围的空洞或重叠？
- 哪些逻辑适合条件表达式，哪些应保留完整 `if` 结构？
