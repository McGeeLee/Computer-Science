# 第5章：循环

## 本章主线

循环让一组语句重复执行。学习重点是证明循环会结束、每次重复都在推进问题，并在结束时得到预期结果。

## 两种主要循环

- `while` 适合重复次数事先未知、由条件或哨兵值决定结束的情况。
- `for` 适合遍历一个序列或明确的数值范围。

两者都可表达许多相同任务，选择标准是哪个更直接地表现问题。嵌套循环用来处理网格、组合和多层重复，但运行次数会相乘。

## 设计一个可靠循环

1. 明确循环开始前需要哪些初始值。
2. 写出继续条件或停止条件。
3. 确认每轮都会更新相关状态，使程序靠近终止。
4. 明确循环结束后哪些性质一定成立。
5. 测试零次、一次、多次和无法正常结束的输入。

累加器、计数器、当前最大值和哨兵值是最常见的状态模式。求和时从什么值开始、范围是否包含终点、更新语句放在哪里，都会产生边界错误。

## 关键概念

- 输入/输出重定向使程序可以用文件批量提供输入并保存输出，便于测试。
- `break` 立即离开当前循环，`continue` 跳到下一轮。它们有时能让意图更清楚，但滥用会使控制流难以分析。
- 浮点累加会积累误差；能用整数计数时尽量用整数，或重新组织计算。
- 蒙特卡罗模拟用大量随机试验估计结果，试验次数增加通常改善统计稳定性，但不消除模型和实现错误。

## 最小练习

分别用 `while` 和 `for` 完成一组整数的统计，输出数量、总和、平均值和最大值；再为零个输入、一个输入和重复最大值设计测试。画出每轮变量值的跟踪表。

## 检查点速答（5.1～5.16）

- **跟踪 `while`（5.1～5.5）**：从 `count=0` 开始、每轮先执行循环体再加 1、条件为 `count < 100` 时，循环体执行 100 次；条件共得到 100 次真和最后 1 次假。初始化、条件或更新任一缺失，都可能产生零次执行、少一次、多一次或无限循环。
- **猜数与哨兵**：循环初值必须保证第一次检查能进入循环；若目标数可能是 0，却把猜测初值也设为 0，程序可能在用户尚未输入时直接结束。以 0 为哨兵输入 `2,3,4,5,0` 时，和为 `14`、有效数据个数为 `4`。
- **`for` 与 `range`（5.6～5.9）**：`range(n)` 迭代 `n` 次；从 0 开始的 `while count < n` 也执行 `n` 次。`range(5, n)` 最多执行 `max(0,n-5)` 次；步长为 3 时，次数是覆盖该半开区间所需的步数。终点不包含在内。
- **嵌套循环**：外层每执行一次，内层就完整执行一轮，总次数通常是各层次数的乘积。画变量跟踪表比凭直觉判断输出更可靠；`break` 只退出它所在的最内层循环。
- **数值循环（5.10～5.13）**：不要靠浮点数逐次相加来期待精确命中终点；可遍历整数后再缩放。求最大公约数时要覆盖 1、两数相等和一数整除另一数等边界，更稳健的方案是欧几里得算法。
- **`break` 与 `continue`（5.14～5.16）**：`break` 立即终止当前循环，`continue` 跳过本轮剩余语句。若 `continue` 跳过了状态更新，`while` 可能永不结束；很多场景可用更准确的循环条件或保护条件改写，使控制流更容易证明。

## 自测

- 一个循环无限执行通常缺少哪三类东西中的哪一类：正确初值、正确条件、有效更新？
- `range` 的终点是否包含在内？这会怎样影响边界？
- 为什么嵌套循环的成本不能只看最内层的一次操作？
