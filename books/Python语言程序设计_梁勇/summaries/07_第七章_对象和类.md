# 第7章：对象和类

## 本章主线

类把一类事物的数据与相关操作组织成一个模型，对象则是这个模型的具体实例。面向对象程序设计的重点不是把所有函数塞进类，而是让程序结构反映问题领域中的概念和责任。

## 核心知识

- 类描述对象应该拥有哪些数据域和方法；构造过程负责建立有效的初始状态。
- `self` 表示当前对象。通过 `对象.成员` 访问数据或调用方法时，操作属于某个具体实例。
- UML 类图用紧凑方式表示类名、数据和操作，有助于在写代码前讨论设计。
- 不可变对象创建后不能原地改变其值；可变对象可以修改内部状态。这个区别会影响参数传递、共享引用和调试。
- 数据隐藏将内部表示与公共接口分离，避免外部代码随意破坏对象状态。
- 类抽象告诉使用者对象能做什么，封装隐藏它怎样完成。

## 从过程到对象

面向过程方式围绕操作分解问题，面向对象方式围绕相互协作的对象组织数据和行为。小程序未必需要类；当一组数据总是被一组操作共同维护、存在明确约束或需要创建多个独立实例时，类通常更自然。

## 设计检查

- 对象是否始终保持合法状态？
- 哪些数据应该由内部维护，哪些操作应该公开？
- 方法是否真正属于这个对象的职责？
- 两个变量是否可能引用同一个可变对象，从而发生意外联动？

## 最小练习

设计一个 `BankAccount` 或 `Course` 类：列出状态、不变量和公共方法；构造两个实例，验证它们的状态互不干扰；尝试非法操作并决定是拒绝、返回状态还是抛出异常。

## 检查点速答（7.1～7.18）

- **类与对象（7.1～7.5）**：类是创建对象的蓝图，对象是类的实例；使用 `class` 定义类，以 `ClassName(...)` 创建对象。`__init__` 在对象创建时建立初始状态，`self` 指当前对象，成员通过 `对象.属性` 或 `对象.方法()` 访问。
- **常见定义错误（7.6～7.10）**：构造实参必须匹配 `__init__`；关键字是小写 `class`；构造方法必须准确命名为 `__init__`；实例方法第一个形参应是 `self`；对象属性要写成 `self.radius`，裸写 `radius` 只是局部名称或未定义名称。
- **UML**：类图通常分为类名、数据域和方法三部分；`+` 表示公共成员，`-` 表示私有成员。UML 是设计和沟通模型，不是 Python 解释器执行的代码。
- **引用与可变性（7.11～7.12）**：若函数收到 `Count` 对象并执行 `c.count = 100`，调用者能看到修改；把形参重新绑定为 `Count(5)` 不会改变调用者原来的引用。对整数形参赋新值同样不改变外部变量。
- **隐藏数据（7.13～7.15）**：双下划线名称会触发名称改写，不应从类外直接依赖；应通过 getter、setter 或更合适的公共方法维护不变量。若在类定义执行前就调用使用该类的 `main()`，会产生 `NameError`。
- **抽象数据类型（7.16～7.18）**：数据隐藏保护表示细节，封装把状态与行为组合，类抽象向客户公开稳定契约。面向过程围绕操作组织数据，面向对象围绕有状态、能协作的对象组织程序；应按问题选择，不必强行使用类。
