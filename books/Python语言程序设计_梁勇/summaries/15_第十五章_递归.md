# 第15章：递归

## 本章主线

递归函数直接或间接调用自身，把一个问题化成规模更小的同类问题。它适合树、目录、分治和自相似结构，但必须同时具备终止条件与可靠的规模缩减。

## 两个组成部分

- 基本情况：不再递归、可以直接求解的最小问题。
- 递归情况：把当前问题转换为更小问题，并利用其结果构造当前答案。

每次调用都有自己的参数和局部变量，并占用调用栈中的一帧。递归深度过大可能耗尽调用栈；同一子问题被反复计算还会造成巨大时间浪费。

## 典型案例

- 阶乘与斐波那契数展示数学定义怎样转成递归，但朴素斐波那契会重复计算。
- 递归选择排序和二分查找展示怎样把数组范围逐步缩小。
- 目录大小天然对应树形文件系统，每个目录包含文件和子目录。
- 汉诺塔把规模为 `n` 的移动分成两个规模为 `n-1` 的同类问题。
- 分形和八皇后分别展示递归生成与回溯搜索。
- 辅助函数可以保存递归所需的额外边界或状态，同时给调用者保留简单接口。

## 递归与迭代

循环通常状态显式、开销较小；递归能更直接表达树形或自相似定义。二者很多时候可以互相转换。选择时应比较可读性、正确性、栈深度和重复计算，而不是把递归当作天然更高级的写法。

尾递归把递归调用放在函数最后一步，但 Python 通常不会自动进行尾调用优化，因此尾递归仍可能受到递归深度限制。

## 跟踪方法

学习递归时不要只看最终输出。为每次调用写下参数、是否命中基本情况、子调用返回什么、当前调用如何组合结果。先画小规模调用树，再运行代码验证。

## 最小练习

实现一个递归求和或二分查找函数，为空输入和单元素输入写出基本情况；画出规模为 4 时的调用过程，再写一个迭代版本比较状态与开销。

## 检查点速答（15.1～15.22）

- **递归定义（15.1～15.6）**：递归函数直接或间接调用自身。`factorial(6)` 若一直递减到 `factorial(0)`，共调用 7 次。幂可定义为 `p(0)=1, p(n)=x*p(n-1)`；前 `n` 个正整数之和可定义为 `s(0)=0, s(n)=n+s(n-1)`。没有可达基本情况或规模不缩小会无限递归；自己调用自己是直接递归，多个函数形成调用环是间接递归。
- **斐波那契与输出跟踪（15.7～15.8）**：朴素 `fib(6)` 共调用 25 次。递归求 `1+...+5` 输出 15；对 1234567 每次打印 `n % 10` 再递归 `n // 10`，会依次输出 `7,6,5,4,3,2,1`。
- **递归结构（15.9～15.12）**：每个递归解都需要基本情况、规模更小的同类调用，以及用子结果构造答案的规则。`isPalindrome("abcba")` 的有效调用链是 `"abcba" → "bcb" → "c"`，随后逐层返回真。调用前打印 `n` 得 `5 4 3 2 1`，调用后打印则得 `1 2 3 4 5`；处理整数数位时应使用 `// 10` 而不是 `/ 10`，并在 0 停止。
- **辅助函数与递归排序（15.13～15.14）**：辅助函数接收公开接口不想暴露的边界或累积状态。递归选择排序 `[2,3,5,1]` 的状态依次是 `[1,3,5,2] → [1,2,5,3] → [1,2,3,5]`，处理区间起点持续右移，直到只剩一个元素。
- **目录与汉诺塔（15.15～15.16）**：`os.path.isfile(path)` 判断是否为文件，`os.path.getsize(path)` 取大小，`os.listdir(path)` 列出目录项；拼路径应优先使用 `os.path.join` 或 `pathlib`。汉诺塔调用次数满足 `T(n)=2T(n-1)+1`，所以 `moveDisks(5,...)` 共调用 31 次，也执行 31 次移动。
- **开销与栈溢出（15.17～15.18）**：递归都能用显式栈等方式改写为非递归；通常比直接迭代多占调用时间和栈空间，但并不总更简单。递归逻辑必须有终止判断，却不一定非要写成某种固定的 `if` 语法；过深或不终止的调用会耗尽调用栈。
- **尾递归（15.19～15.22）**：递归调用返回后没有待完成操作就是尾递归；递归选择排序的递归调用之后无工作，因此属于尾递归。斐波那契可用辅助状态 `fib_helper(n,a,b)`：`n==0` 返回 `a`，否则 `return fib_helper(n-1,b,a+b)`。但 Python 不做尾调用优化，这种写法仍增长调用栈，实际求大 `n` 更适合循环。
