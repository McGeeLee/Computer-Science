# 第13章：文件和异常处理

## 本章主线

文件让数据跨越程序运行而长期保存，异常让程序对失败作出结构化反应。本章把此前主要处理内存数据的程序带入真实输入、外部资源和不可靠环境。

## 文件处理

- `open()` 需要文件路径和模式；读、写、追加具有不同的覆盖风险。
- 文本文件读写字符串，数值需要在文本与数值类型之间转换。
- `read()`、`readline()`、`readlines()` 和逐行迭代在内存占用及使用方式上不同。
- 文件存在性检查可以改善用户体验，但检查与真正打开之间仍可能发生变化，所以实际打开操作仍需处理失败。
- GUI 文件对话框只负责选择路径，真正的读写和错误处理应由独立逻辑完成。
- 网络资源同样可能失败，且还涉及编码、超时和内容变化。

现代 Python 中通常使用 `with open(...)` 管理文件生命周期，使文件在正常或异常路径上都能关闭。书中概念仍适用，具体写法应结合当前版本实践。

## 异常处理

- `try` 包围可能失败的操作，`except` 处理明确知道怎样应对的异常，`finally` 执行无论成功失败都需要的清理。
- `raise` 主动报告违反前置条件或无法继续的情况。
- 捕获到异常对象后，可以读取有助于诊断的信息。
- 自定义异常类用于表达领域特有失败，让调用者区别不同原因。

异常处理的目标不是让所有错误消失。过于宽泛地捕获并忽略异常，会把真正原因隐藏起来。应该只在能够恢复、补充上下文或转换抽象层次时捕获，否则让异常继续传播。

## 二进制对象存储

`pickle` 能保存和恢复 Python 对象，但其格式与 Python 紧密相关，而且反序列化不可信数据存在安全风险。只应加载可信来源的数据；跨系统交换通常需要更明确、可验证的格式。

## 最小练习

编写词数统计工具：逐行读取文本，处理文件不存在和编码问题，输出统计结果；再故意提供错误路径、空文件和异常内容，检查错误信息是否对使用者有帮助。
