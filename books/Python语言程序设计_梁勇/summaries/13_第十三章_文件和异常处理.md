# 第13章：文件和异常处理

## 本章主线

文件让数据跨越程序运行而长期保存，异常让程序对失败作出结构化反应。本章把此前主要处理内存数据的程序带入真实输入、外部资源和不可靠环境。

## 文件处理

- `open()` 需要文件路径和模式；读、写、追加具有不同的覆盖风险。
- 文本文件读写字符串，数值需要在文本与数值类型之间转换。
- `read()`、`readline()`、`readlines()` 和逐行迭代在内存占用及使用方式上不同。
- 文件存在性检查可以改善用户体验，但检查与真正打开之间仍可能发生变化，所以实际打开操作仍需处理失败。
- GUI 文件对话框只负责选择路径，真正的读写和错误处理应由独立逻辑完成。
- 网络资源同样可能失败，且还涉及编码、超时和内容变化。

现代 Python 中通常使用 `with open(...)` 管理文件生命周期，使文件在正常或异常路径上都能关闭。书中概念仍适用，具体写法应结合当前版本实践。

## 异常处理

- `try` 包围可能失败的操作，`except` 处理明确知道怎样应对的异常，`finally` 执行无论成功失败都需要的清理。
- `raise` 主动报告违反前置条件或无法继续的情况。
- 捕获到异常对象后，可以读取有助于诊断的信息。
- 自定义异常类用于表达领域特有失败，让调用者区别不同原因。

异常处理的目标不是让所有错误消失。过于宽泛地捕获并忽略异常，会把真正原因隐藏起来。应该只在能够恢复、补充上下文或转换抽象层次时捕获，否则让异常继续传播。

## 二进制对象存储

`pickle` 能保存和恢复 Python 对象，但其格式与 Python 紧密相关，而且反序列化不可信数据存在安全风险。只应加载可信来源的数据；跨系统交换通常需要更明确、可验证的格式。

## 最小练习

编写词数统计工具：逐行读取文本，处理文件不存在和编码问题，输出统计结果；再故意提供错误路径、空文件和异常内容，检查错误信息是否对使用者有帮助。

## 检查点速答（13.1～13.32）

- **打开文件（13.1～13.4）**：`open(path, "r")` 读取，`"w"` 写入并截断已有内容，`"a"` 追加。Windows 路径中的 `\b`、`\t` 等可能被当作转义，应使用原始字符串、双反斜杠或 `pathlib.Path`。读取不存在的文件抛出 `FileNotFoundError`，写入不存在的文件通常会创建它；存在性可用 `os.path.exists()`/`isfile()` 检查，但真正打开仍需处理异常。
- **读取与写入（13.5～13.13）**：`read(30)` 读最多 30 个字符，`read()` 读完剩余内容，`readline()` 读一行，`readlines()` 返回行列表；文件末尾继续读返回空字符串而非报错。`write()` 写字符串，数值写入前用 `str()`，读回后用 `int()`/`float()`。原始字符串字面量写作 `r"..."`。
- **文件对话框（13.14～13.15）**：`askopenfilename()` 选择现有文件，`asksaveasfilename()` 选择保存路径；用户取消时应先检查空结果，再进行读写。
- **网页数据（13.16～13.17）**：可用 `urllib.request.urlopen(url)` 打开 URL，再读取并按响应编码解码；`repr(s)` 返回带转义的字符串表示。网络访问还应处理超时、HTTP 错误和不可信内容。
- **异常控制流（13.18～13.22）**：`try` 中某语句抛异常后，后续语句跳过；匹配的 `except` 执行后继续到结构之后，未捕获异常则向外传播。`finally` 无论是否匹配都会执行，但未捕获异常会在它之后继续传播。数组越界示例输出 `Index out of bound`；除零会被 `ZeroDivisionError` 分支捕获。
- **`else`、`finally` 与抛出（13.23～13.28）**：用 `raise ExceptionType(...)` 主动抛出。`else` 仅在 `try` 无异常时运行，`finally` 始终运行：成功示例依次输出 `Done`、`Nothing is wrong`、`Finally we are here`、`Continue`；越界示例输出错误提示、`Finally we are here`、`Continue`。子类异常如 `ZeroDivisionError` 必须放在父类 `ArithmeticError` 之前；自定义异常通常继承 `Exception`。
- **对象文件（13.29～13.32）**：`wb`/`rb` 以二进制模式写读，`pickle.dump(obj, file)` 保存对象，`pickle.load(file)` 读取。若把 `close()` 放在循环内的 `finally`，第一次迭代就关闭文件，下一次读取会报“对已关闭文件操作”；`except` 不能脱离 `try`。切勿对不可信文件执行 `pickle.load()`。
