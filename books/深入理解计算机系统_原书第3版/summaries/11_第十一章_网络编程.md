# 第11章：网络编程

## 核心问题

怎样把跨主机通信转化为程序能够使用的 I/O？本章采用客户端—服务器模型，把网络连接抽象为套接字端点，并在此基础上构建 echo 服务和微型 Web 服务器。

## 网络程序员模型

从程序视角看，互联网在不同主机进程之间传送字节。IP 地址标识网络接口，端口标识主机上的服务端点，域名提供人可读命名，连接由两个端点共同确定。DNS 名字、IP 地址、端口和应用层资源路径属于不同命名层，不能相互替代。

字节序也跨越层次：协议字段使用网络字节序，主机整数可能使用不同顺序。现代代码应优先使用能够处理多种地址族的名称解析接口，避免把 IPv4 字符串和固定结构写死在业务逻辑中。

## 套接字接口

客户端通常创建套接字并 `connect` 到服务器。服务器创建套接字，绑定本地地址，进入监听状态，再用 `accept` 为每个已建立连接取得新的已连接描述符。监听描述符负责接收连接请求，已连接描述符负责和一个客户端交换数据，两者职责不同。

连接是字节流而非消息队列；一次 `write` 不对应对端一次 `read`。应用协议必须自己定义消息边界，例如固定长度、长度字段、分隔符或连接关闭，并正确处理短读短写。

## Web 与 Tiny 服务器

HTTP 请求和响应展示了应用层协议如何在字节流上约定方法、路径、首部和正文。静态内容直接读取文件，动态内容通过程序生成。Tiny 服务器的价值是串起解析、文件元数据、描述符和进程，而不是作为生产级 Web 服务器模板；输入验证、路径安全、并发、超时、TLS 和完整协议兼容都还需要额外设计。

## 版本意识

本章偏 IPv4 和早期 HTTP 教学模型。套接字、端点、字节流、名称解析和客户端—服务器等机制仍然重要，但今天的 Web 普遍还涉及 TLS、反向代理、HTTP/2 或 HTTP/3、IPv6、服务发现和异步运行时。学习时保留机制，更新具体生态。

## 动手验证

先写一个能正确处理短读写的 echo 客户端/服务器，再让服务器提供一个固定文件；用 `curl` 或抓包工具观察真实请求和响应。Proxy Lab 能进一步练习并发、缓存和鲁棒 I/O。
