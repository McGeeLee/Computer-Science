# 第10章：系统级 I/O

## 核心问题

Unix 把外设、普通文件、目录、管道和网络套接字统一成“文件”接口。程序通过文件描述符对字节序列进行打开、读取、写入和关闭。本章建立后续网络与并发服务器的公共 I/O 基础。

## 文件描述符与系统调用

文件描述符是进程级小整数，指向内核维护的打开文件状态。进程通常从描述符 0、1、2 获得标准输入、标准输出和标准错误。`open` 返回新描述符，`close` 释放引用；错误检查不能省略，否则后续调用会掩盖真正原因或泄漏资源。

`read` 和 `write` 允许短计数：返回值可能小于请求字节数，这并不必然是错误。中断、管道、终端和网络尤其常见。必须循环处理剩余字节，并区分 EOF、可重试条件和真正错误。

## RIO

书中的 Robust I/O 包装函数提供两种模式：无缓冲的可靠传输适合把固定字节数搬完，带缓冲读取适合逐行文本协议。它们展示了如何把短计数和中断等复杂性封装在稳定接口后，但使用时仍要明确是二进制数据、文本行还是未知长度流。

## 元数据、目录与共享

`stat` 一类接口读取文件类型、大小和权限等元数据。目录是名字到文件的映射，遍历目录要处理特殊项和错误。内核中的描述符表、打开文件表和文件节点表解释了多个描述符、`fork` 后父子进程以及重复打开同一文件时，哪些状态共享，哪些独立；尤其要注意共享文件位置。

## 重定向与标准 I/O

描述符复制让 Shell 能把程序标准输入输出连接到文件、管道或套接字，而程序本身无需知道目标设备。C 标准 I/O 在描述符上增加用户态缓冲和格式化，使用方便；但与底层 I/O 混用时会因缓冲状态不一致产生问题。网络套接字通常更适合明确控制的 Unix I/O 或专门封装。

## 学完应能做到

写出处理短读短写的复制循环；解释重定向为何不需要修改被启动程序；画出父子进程共享描述符后的内核引用关系；在所有路径正确关闭资源。
